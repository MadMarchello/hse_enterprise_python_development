**Дисциплина: «Промышленное программирование на Python»**

Цель работы — пройти полный минимальный цикл создания небольшого Python-проекта: структурировать код, использовать базовые типы данных, сформировать воспроизводимое окружение, написать тест, применить хеширование, выполнить интеграцию с внешним сервисом и зафиксировать этапы разработки в Git. Использование LLM разрешено и рекомендуется, но полученный код необходимо понимать и проверять.

# 1. Структура проекта

Создайте отдельный проект со следующей структурой:

```
homework-01/
├── src/
│   └── homework/
│       ├── __init__.py
│       └── main.py
├── tests/
├── README.md
├── requirements.txt
├── pyproject.toml
└── .gitignore
```

Проект должен запускаться в отдельном виртуальном окружении `.venv`. Каталог `.venv` не должен попадать в Git.

# 2. Демонстрация типов данных Python

Программа должна создать и вывести значения как минимум следующих встроенных типов:

- `int`
- `float`
- `bool`
- `str`
- `list`
- `tuple`
- `set`
- `dict`

Для каждого значения необходимо вывести само значение и его фактический тип, например:

```python
x = 42
print(x, type(x))
```

# 3. Формирование отчёта и вычисление хешей

Весь результат вывода о типах данных необходимо собрать в одну строку (отчёт). В начало или конец отчёта добавьте своё ФИО.

От одного и того же UTF-8 представления итогового отчёта вычислите два хеша:

- MD5
- SHA-256

Важно: оба алгоритма должны получать одинаковую последовательность байтов. Не вычисляйте один хеш от ФИО, а другой — от отдельной части отчёта.

# 4. Отправка результата по электронной почте

Программа должна сформировать и отправить электронное письмо, содержащее ФИО студента, MD5 и SHA-256 итогового отчёта.

```
ФИО: Иванов Иван Иванович

MD5:
<полученный хеш>

SHA-256:
<полученный хеш>
```

**Требование по безопасности:** пароли, SMTP-токены и другие учётные данные запрещено хранить непосредственно в исходном коде и фиксировать в Git. Способ безопасной передачи credentials в программу необходимо найти самостоятельно.

# 5. Автоматический тест

Вынесите вычисление хешей в отдельную функцию и напишите для неё как минимум один тест с использованием pytest.

```python
def calculate_hashes(text: str) -> tuple[str, str]:
    ...
```

Тест должен проверять результат на заранее известной строке. Результат желательно независимо сверить внешним инструментом, а не считать правильным только потому, что программа его вывела.

# 6. Работа с Git

Проект должен быть локальным Git-репозиторием. Сделайте не менее трёх осмысленных commit'ов, отражающих этапы разработки.

```bash
git init
git add ...
git commit -m "..."
```

Пример логики истории:

1. Initial project structure
2. Add datatype report and hashing
3. Add tests and email delivery

Названия commit'ов могут быть другими. Важна не формальность количества, а фиксация осмысленных состояний проекта.

# 7. Использование LLM

Разрешается использовать любую LLM для генерации, объяснения, отладки и улучшения программы.

В README.md необходимо указать:

- какая LLM использовалась;
- основные prompts, с помощью которых создавался или исправлялся код;
- что именно в ответах LLM вы проверяли;
- как минимум одну ошибку, неточность или неудачное решение LLM, которое вы обнаружили и исправили. Если существенных ошибок обнаружено не было — укажите это и опишите, каким способом вы проверяли корректность результата.

# 8. Что должно быть готово к сдаче

| Проверка | Ожидаемый результат |
| --- | --- |
| Структура проекта | src layout, tests, README.md, pyproject.toml, requirements.txt, .gitignore |
| Окружение | `.venv` создаётся локально и не хранится в Git |
| Запуск программы | Программа выводит типы, формирует отчёт, MD5 и SHA-256 |
| Email | Письмо с ФИО и двумя хешами успешно отправляется |
| Тесты | `pytest -q` завершается успешно |
| Git | Не менее 3 осмысленных commit'ов |
| README.md | Описание запуска, LLM и prompts, результаты проверки LLM |

# 9. Минимальная демонстрация при сдаче

Будьте готовы показать преподавателю выполнение следующих действий:

```bash
git log --oneline
git status
pytest -q
python -m homework.main
```

Также необходимо продемонстрировать полученное электронное письмо. Архив ZIP не является заменой Git-репозиторию.

# Ключевой принцип задания

**Работающий код → воспроизводимый проект → проверяемый результат → управляемая история изменений.**
